# Security Policy & Threat Model

## Honest Threat Model

Ringwall is a **defense-in-depth Linux runtime containment, CVE/drift self-healing, and local/uncensored AI triage system**. No OS or security daemon can promise "zero vulnerabilities", and **no AI can magically discover and safely live-patch unknown zero-day source code in production**. Instead, Ringwall combines deterministic kernel pre-execution blocking, automated CVE patching, TTL-bounded zero-day virtual patching, and signed A/B immutable updates.

### What Ringwall Prevents, Detects & Remediates (v0.2)
- **Synchronous Pre-Read & Pre-Exec Kernel Blocking (eBPF LSM, Tier 1):** On kernels booted with `lsm=...,bpf` (enabled by default in the Ringwall Appliance ISO via `lsm=lockdown,yama,integrity,apparmor,bpf`), `lsm/file_open` resolves paths in-kernel via `bpf_d_path` AND checks pinned secret inodes (`lsm_deny_file_inodes`) + non-spoofable caller executable `(s_dev, i_ino)` (`allowed_ssh_exe_inodes`) — returning **`-EPERM` synchronously BEFORE a single byte is read**. This defeats direct SSH private-key reads, `//home`, `/usr/../home`, symlinks, TOCTOU races, `/tmp/ssh` copies, `PR_SET_NAME` spoofing, chroot/dot-directories (`/.ssh`, `/tmp/alt/.ssh`), **hardlinks to existing keys**, and **source-renames of existing keys**. `lsm/bprm_check_security` synchronously blocks execution (`-EPERM`) of zero-day virtual-patched binaries.
- **Zero-TOCTOU Tracing Fallback (Tier 2/3):** On hosts without `lsm=...,bpf`, `fentry/security_file_open` + `bpf_d_path` (`EVENT_OPEN_RESOLVED`) still resolves file opens in-kernel without userspace `readlink` TOCTOU, falling back cleanly to hardened `sys_enter_openat*` tracepoints on older non-BTF kernels.
- **Post-Exploitation & Persistence Containment:** Reverse shell `execve` patterns, destructive recursive `rm` (with `--r`/`--rec`, without `-f`, relative targets via `Cwd`), `rename`/`renameat`/`renameat2`/`link`/`linkat`/`symlink`/`symlinkat` persistence writes (using parent-only symlink resolution via `EVENT_LINK_DEST` so `symlink(..., ~/.ssh/authorized_keys)` never resolves away from `authorized_keys`), `io_uring_setup` freeze (`RW-CORE-007`), and outbound C2 connections (`connect` + `sendto`).
- **Continuous CVE, CISA KEV, Stale-Library & Drift Self-Healing:**
  - Deterministic local inventory (`/var/lib/dpkg/status`, `/lib/apk/db/installed`, `/proc/*/maps` deleted `.so` detection, kernel sysctl + `0600` permission drift) correlated against HTTPS **OSV.dev + CISA KEV** (opt-in `allow_online_feeds`) and/or airgapped offline advisory bundles (`offline_db_path`).
  - **Host Auto-Patcher:** security-only `apt-get install --only-upgrade` with strict package-name regex validation (zero shell execution), post-patch restart of non-protected stale services (`systemctl is-active` verified; `ringwalld`, `sshd`, `dbus`, `systemd-*` protected against lockout), and baseline drift remediation.
  - **Zero-Day Virtual Patcher:** when an active KEV/Critical/High CVE has **no upstream fix yet**, Ringwall synthesizes a temporary declarative Ringwall policy rule (optionally assisted by the uncensored AI Guardian, ALWAYS validated against hard anti-lockout blocklists covering `ringwalld`, `systemd`, `bash`, `sh`, `login`, `sshd`, `apt-get`, `dpkg`, and overbroad globs like `/**`), activates synchronous `lsm/bprm_check_security` blocking where available, enforces a mandatory TTL (default 72h, max 168h), and auto-revokes the rule once a subsequent scan confirms the upstream patch is installed.
  - **Signed A/B Immutable Appliance Updates:** Ed25519 signature verification (`VerifyManifest`), anti-downgrade monotonicity, SHA-256 + byte-length verification before staging to the inactive slot, and boot-counter automatic rollback (`ConfirmBootHealth`) if the new slot fails startup health checks.
- **Unprivileged tamper attempts:** `/run/ringwall/api.token`, `/var/log/ringwall/audit.jsonl`, and `/var/lib/ringwall/ab-state.json` are strictly `0600 root:root`.

### Explicit Limitations & Non-Goals (Read Carefully!)
- **Hosts without `lsm=...,bpf`:** When a Linux host kernel is NOT booted with `lsm=...,bpf`, Ringwall falls back to `fentry/security_file_open` (asynchronous `SIGSTOP` after open). The initial read can complete before `SIGSTOP` lands; enable `lsm=...,bpf` (as the Ringwall ISO does) for synchronous `-EPERM` pre-read blocking.
- **Newly created keys & inode pinning:** `lsm_deny_file_inodes` pins existing SSH private key inodes at daemon startup (blocking hardlinks and source-renames of those keys synchronously). Path-based `lsm/file_open` catches newly created keys immediately under `**/.ssh/id_*`, while hardlinks made to a key created *after* daemon startup are only caught once pinned on reload/restart.
- **`rename*`/`link*`/`symlink*` destinations & `bpf_d_path` >255B:** Syscall tracepoints for `rename*`/`link*`/`symlink*` still resolve parent directory symlinks asynchronously in userspace. Paths whose canonical `d_path` exceeds 255 bytes (`ENAMETOOLONG`) cannot fit in the fixed 256-byte ringbuf slot.
- **Non-Debian userns sysctl:** `-kernel.unprivileged_userns_clone = 0` applies on Debian/Ubuntu kernels (including the Ringwall ISO). On upstream kernels lacking that sysctl (Fedora/Arch/RHEL), configure `user.max_user_namespaces=0` or AppArmor userns restrictions if workloads do not require unprivileged namespaces.
- **`SIGSTOP` vs cgroup v2 freezer:** For tracepoint-triggered freezes (`execve`, `io_uring`, `rename*`) in a shared interactive session, another same-UID process could theoretically send `SIGCONT`. Ringwall freezes known AI-agent ancestors alongside the child and uses root-owned `cgroup.freeze` whenever a workload runs in a dedicated container/agent cgroup.
- **Zero-day virtual patch boundaries:** Virtual patches contain *known* unpatched CVEs (or operator-specified binaries/ports) via declarative Ringwall rules; Ringwall never lets an LLM compile C code or modify system binaries in production.
- **Audit log & cloud AI boundaries:** SHA-256 hash chaining detects non-root tampering; forward logs off-host for root-compromise forensics. Opting into cloud uncensored APIs (Venice.ai / OpenRouter) sends redacted incident/advisory metadata over HTTPS — use **Local Ollama** or **llama.cpp** for strict airgapped privacy.
- **Kernel 0-days, root compromise, CPU side-channels & firmware bugs:** Outside userspace daemon scope; pair with hardware virtualization (e.g., Qubes OS / Firecracker microVMs) for strict multi-tenant isolation.

## Security Invariants

1. **Deterministic Policy & Kernel LSM Win:** `guardian.EnforceInvariant` guarantees no LLM output can downgrade a deterministic verdict; AI-proposed virtual patches ALWAYS pass hard deterministic anti-lockout validation.
2. **Block/Freeze First, Analyze Second:** Synchronous eBPF LSM `-EPERM` (or `pidfd`-verified `SIGSTOP`) executes before LLM latency; slow AI responses can never overwrite operator decisions.
3. **Root-Only Control Plane & Cryptographic Integrity:** Control API (`127.0.0.1:9443`) authenticates via `0600 root:root` bearer token; API keys live in separate `0600` files; A/B appliance updates require Ed25519 signature + SHA-256 + anti-downgrade verification.
4. **Zero Shell Execution in Enforcement & Patching:** `nftables`, `apt-get`, and `systemctl` are invoked strictly via direct `exec.CommandContext` argv with strict allowlist/regex input validation.

Please report security vulnerabilities privately via GitHub Security Advisories on `samyxo-bv/ringwall` rather than opening a public issue.
