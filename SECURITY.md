# Security Policy & Threat Model

## Honest Threat Model

Ringwall is a **defense-in-depth Linux runtime containment, CVE/drift self-healing, and local/uncensored AI triage system**. No OS or security daemon can promise "zero vulnerabilities", and **no AI can magically discover and safely live-patch unknown zero-day source code in production**. Instead, Ringwall combines deterministic kernel pre-execution blocking, automated CVE patching, TTL-bounded zero-day virtual patching, and signed A/B immutable updates.

### What Ringwall Prevents, Detects & Remediates (v0.2)
- **Fail-Closed Synchronous Pre-Read & Pre-Exec Kernel Blocking (eBPF LSM, Tier 1):** On kernels booted with `lsm=...,bpf` (enabled by default in the Ringwall Appliance ISO via `lsm=lockdown,yama,integrity,apparmor,bpf`), four LSM hooks enforce synchronously inside the kernel:
  - `lsm/file_open`: resolves paths via `bpf_d_path` into a per-CPU scratch buffer and evaluates pinned secret inodes (`lsm_deny_file_inodes`) + non-spoofable caller executable `(s_dev, i_ino)` (`allowed_ssh_exe_inodes`, defaulting to `ssh-agent`, `ssh-add`, `ssh-keygen` — **`ssh` itself is NOT allowlisted by default** to defeat the `ssh -F ~/.ssh/id_*` GTFOBins key-leak oracle; use `ssh-agent`/`ssh-add` or FIDO2 keys, or configure `sensor.lsm_allowed_ssh_exes` including `[]` for zero exemptions) **BEFORE** reserving ringbuf space — returning **`-EPERM` synchronously BEFORE a single byte is read, even under a deliberate ringbuf saturation flood**. Also revokes the SSH binary exemption immediately whenever `task->ptrace != 0` (defeating pre-exec `strace` / `PTRACE_TRACEME` even if `yama.ptrace_scope <= 1`). Defeats direct SSH private-key reads by non-allowlisted tools, `ssh -F`, `//home`, `/usr/../home`, symlinks, TOCTOU races, `/tmp/ssh` copies, `PR_SET_NAME` spoofing, chroot/dot-directories (`/.ssh`, `/tmp/alt/.ssh`), **hardlinks to existing keys**, and **source-renames of existing keys**.
  - `lsm/mmap_file`: synchronously returns **`-EPERM` (fail-closed)** whenever an allowlisted SSH binary attempts to map any non-root-owned or group/world-writable (`mode & 0022`) `PROT_EXEC` object — defeating `LD_PRELOAD`, `PKCS11Provider`, `fork()`, and `pthread_create()` hijacks before a single attacker instruction can run.
  - `lsm/ptrace_access_check`: blocks non-root `ptrace` attachment into allowlisted SSH binaries (paired with `task->ptrace != 0` revocation in `lsm/file_open` for pre-exec tracers).
  - `lsm/bprm_check_security`: synchronously blocks execution (`-EPERM`) of zero-day virtual-patched binaries, populated using `O_NOFOLLOW` on the final path component + live refreshed protected-inode filtering (re-statted on every sync, scan tick, and immediately after `apt-get` upgrades) + `FS_IOC_GETVERSION` (`inode->i_generation`) verification on persistent filesystems (`ext4`/`xfs`/`btrfs`) so reused inode numbers never falsely block newly installed system binaries.
- **Zero-TOCTOU Tracing Fallback (Tier 2/3):** On hosts without `lsm=...,bpf`, `fentry/security_file_open` + `bpf_d_path` (`EVENT_OPEN_RESOLVED`) still resolves file opens in-kernel without userspace `readlink` TOCTOU, falling back cleanly to hardened `sys_enter_openat*` tracepoints on older non-BTF kernels.
- **Post-Exploitation & Persistence Containment:** Reverse shell `execve` patterns, destructive recursive `rm` (with `--r`/`--rec`, without `-f`, relative targets via `Cwd`), `rename`/`renameat`/`renameat2`/`link`/`linkat`/`symlink`/`symlinkat` persistence writes (using parent-only symlink resolution via `EVENT_LINK_DEST` so `symlink(..., ~/.ssh/authorized_keys)` never resolves away from `authorized_keys`), `io_uring_setup` freeze (`RW-CORE-007`), and outbound C2 connections (`connect` + `sendto`).
- **Continuous CVE, CISA KEV, Stale-Library & Drift Self-Healing:**
  - Deterministic local inventory (`/var/lib/dpkg/status`, `/lib/apk/db/installed`, `/proc/*/maps` deleted `.so` detection, kernel sysctl + `0600` permission drift) correlated against HTTPS **OSV.dev + CISA KEV** (opt-in `allow_online_feeds`) and/or airgapped offline advisory bundles (`offline_db_path`), with deterministic sorted OSV batching and fail-closed `Complete` status tracking.
  - **Host Auto-Patcher:** security-only `apt-get install --only-upgrade` with strict package-name regex validation (zero shell execution), post-patch restart of non-protected stale services (`systemctl is-active` verified; `ringwalld`, `sshd`, `dbus`, `systemd-*`, `user@*.service` protected against lockout), and baseline drift remediation.
  - **Zero-Day Virtual Patcher:** when an active KEV/Critical/High CVE has **no upstream fix yet**, Ringwall synthesizes a temporary declarative Ringwall policy rule (optionally assisted by the uncensored AI Guardian, ALWAYS restricted to `freeze`/`block_egress` and validated against live `(dev, ino)` anti-lockout indices covering `/etc/shells`, usrmerge aliases, `sshd`/`sshd-session`/`sshd-auth`, `systemd*`, `dbus*`, `apt-get`/`dpkg`, `ringwalld`, rejecting symlinks, `**`/`..` globs, shallow/system/login prefixes such as `/root`, `/etc/pam.d`, `/etc/sudoers.d`, `/.ssh`, and user dotfiles, and critical ports `22/53/80/443/9443`). At runtime, `policy.Engine` ALSO refuses to match any virtual rule against a protected executable (`vpExeGuard`), and `SyncBlockedExecPaths` opens target binaries with `O_NOFOLLOW` on the final path component + live refreshed protected-inode filtering + `FS_IOC_GETVERSION` (`i_generation`) verification on every sync, scan, and post-`apt-get` upgrade. Native TTL state persists in `0600` `/var/lib/ringwall/virtual-patches.json` (reloading both policy rules and `lsm_deny_exec_inodes` across restarts), and `Reconcile` **never auto-revokes on incomplete/errored/paginated feeds**.
  - **Signed A/B Immutable Updates (Experimental for Disk-Installed Bootloaders):** Ed25519 signature verification (`VerifyManifest`), anti-downgrade monotonicity (`MinVersion`), redirect & `O_EXCL` symlink-safe staging, SHA-256 + byte-length verification, and `/proc/cmdline` `ringwall.slot=A|B` boot-confirmed promotion/rollback (`ConfirmBootHealth` only promotes after an actual reboot into `PendingSlot`).
- **Unprivileged tamper attempts:** `/run/ringwall/api.token`, `/var/log/ringwall/audit.jsonl`, `/var/lib/ringwall/virtual-patches.json`, and `/var/lib/ringwall/ab-state.json` are strictly `0600 root:root`.

### Explicit Limitations & Non-Goals (Read Carefully!)
- **Hosts without `lsm=...,bpf`:** When a Linux host kernel is NOT booted with `lsm=...,bpf`, Ringwall falls back to `fentry/security_file_open` (asynchronous `SIGSTOP` after open). The initial read can complete before `SIGSTOP` lands; enable `lsm=...,bpf` (as the Ringwall ISO does) for synchronous `-EPERM` pre-read blocking.
- **Same-UID allowlisted SSH binary limits on host installs:** On the immutable Ringwall ISO, OpenSSH is not installed (`allowed_ssh=0`). On multi-purpose Linux hosts, `ssh` is excluded from the default allowlist to block `ssh -F <private_key>` exfiltration; remaining allowlisted helpers (`ssh-agent`, `ssh-add`, `ssh-keygen`) running under the same UID can still face living-off-the-land vectors if unencrypted keys sit on disk (for example, pointing `SSH_AUTH_SOCK` at a rogue socket with `ssh-add`, or triggering a core dump on `ssh-keygen -p` when `fs.suid_dumpable != 0` / `RLIMIT_CORE > 0`). Protect keys with strong passphrases or FIDO2/hardware tokens, keep `fs.suid_dumpable=0`, or set `sensor.lsm_allowed_ssh_exes: []` in `ringwall.yaml` for zero-exemption kernel lockdown.
- **Newly created keys & pinned-inode reuse:** `lsm_deny_file_inodes` pins existing SSH private key inodes at daemon startup (blocking hardlinks and source-renames of those keys synchronously). Path-based `lsm/file_open` catches newly created keys immediately under `**/.ssh/id_*`, while hardlinks to a key created *after* daemon startup are pinned on reload/restart. Conversely, if a pinned key is deleted and the filesystem later reuses that exact `(s_dev, i_ino)` for another file before restart, restart/reload `ringwalld` to refresh pinned inodes. (For `lsm_deny_exec_inodes`, `inode->i_generation` plus post-patch live refresh eliminates inode-reuse lockouts on `ext4`/`xfs`/`btrfs`.)
- **A/B slot switching on live ISO vs disk-installed appliances:** The bootable live ISO runs from read-only SquashFS on `ringwall.slot=A` (verify/sign tooling works live, while real two-partition A/B switching & boot-counter rollback is experimental and requires a disk-installed bootloader such as GRUB/systemd-boot configured to read `/var/lib/ringwall/ab-boot.env` and pass `ringwall.slot=A|B` to the kernel).
- **`rename*`/`link*`/`symlink*` destinations & `bpf_d_path` >255B:** Syscall tracepoints for `rename*`/`link*`/`symlink*` still resolve parent directory symlinks asynchronously in userspace. Paths whose canonical `d_path` exceeds 255 bytes (`ENAMETOOLONG`) cannot fit in the fixed 256-byte ringbuf slot.
- **Non-Debian userns sysctl:** `-kernel.unprivileged_userns_clone = 0` applies on Debian/Ubuntu kernels (including the Ringwall ISO). On upstream kernels lacking that sysctl (Fedora/Arch/RHEL), configure `user.max_user_namespaces=0` or AppArmor userns restrictions if workloads do not require unprivileged namespaces.
- **`SIGSTOP` vs cgroup v2 freezer:** For tracepoint-triggered freezes (`execve`, `io_uring`, `rename*`) in a shared interactive session, another same-UID process could theoretically send `SIGCONT`. Ringwall freezes known AI-agent ancestors alongside the child and uses root-owned `cgroup.freeze` whenever a workload runs in a dedicated container/agent cgroup.
- **Zero-day virtual patch boundaries:** Virtual patches contain *known* unpatched CVEs (or operator-specified binaries/ports) via declarative Ringwall rules; Ringwall never lets an LLM compile C code or modify system binaries in production.
- **Audit log & cloud AI boundaries:** SHA-256 hash chaining detects non-root tampering; forward logs off-host for root-compromise forensics. Opting into cloud uncensored APIs (Venice.ai / OpenRouter) sends redacted incident/advisory metadata over HTTPS — use **Local Ollama** or **llama.cpp** for strict airgapped privacy.
- **Kernel 0-days, root compromise, CPU side-channels & firmware bugs:** Outside userspace daemon scope; pair with hardware virtualization (e.g., Qubes OS / Firecracker microVMs) for strict multi-tenant isolation.

## Security Invariants

1. **Deterministic Policy & Kernel LSM Win:** `guardian.EnforceInvariant` guarantees no LLM output can downgrade a deterministic verdict; AI-proposed virtual patches ALWAYS pass hard deterministic anti-lockout validation.
2. **Block/Freeze First, Analyze Second:** Synchronous eBPF LSM `-EPERM` (or `pidfd`-verified `SIGSTOP`) executes before LLM latency; slow AI responses can never overwrite operator decisions.
3. **Root-Only Control Plane & Cryptographic Integrity:** Control API (`127.0.0.1:9443`) authenticates via `0600 root:root` bearer token; API keys live in separate `0600` files; A/B appliance updates require Ed25519 signature + SHA-256 + anti-downgrade verification.
4. **Zero Shell Execution in Enforcement & Patching:** `nftables`, `apt-get`, and `systemctl` are invoked strictly via direct `exec.CommandContext` argv with strict allowlist/regex input validation.
